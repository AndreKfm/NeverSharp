# M3 + M4: AST factory and parser (Track F) — brief for porting attempts

Modules M3 and M4 of [phase1-plan.md](../phase1-plan.md) §4, ported together: the factory has no gate of its own and is checked through the parser's AST dump. Every attempt receives exactly this brief and the inputs it names (pre-registration §5.2). Written by the orchestrator before any attempt started. The standing rules of [README.md](README.md) apply.

## Scope

The 950 units (13,203 lines) listed in [M34-units.md](M34-units.md) (generated by `harness/port/modules.mjs --module M34`):

- `factory/nodeFactory.ts`: `createNodeFactory` and the 223 inner functions the parser reaches (the `create*`/`update*` functions with their `TransformFlags` propagation, `asName`, …), plus `factory/emitNode.ts`, `factory/utilities.ts`, `factory/nodeTests.ts`, `factory/utilitiesPublic.ts`, and the null implementations `nullParenthesizerRules`, `nullNodeConverters` (the parser's factory is created with `NoParenthesizerRules | NoNodeConverters`);
- `parser.ts`: `createSourceFile`, `namespace Parser` (all of it except `namespace JSDocParser`), `parseJsonText`, `isExternalModule`, `forEachChildRecursively`, pragma processing, …;
- the rest of `utilities.ts` and `utilitiesPublic.ts` that the parser reaches; `convertToJson` (commandLineParser.ts); `commentPragmas` (types.ts).

Not in this module (named in M34-units.md): `forEachChild`/`forEachChildTable` (generated: `NodeVisitor.ForEachChild` in `src/NeverSharp.Faithful/Generated/`); `namespace JSDocParser`, `parseIsolatedJSDocComment`, `parseJSDocTypeExpressionForTests` (module M5); `namespace IncrementalParser` and `createSyntaxCursor` (no incremental parsing in Phase 1: the parser runs with `syntaxCursor` undefined, and the code that tests it is ported as it is); `createParenthesizerRules`, `createNodeConverters`; performance and tracing calls (instrumentation; left out).

**JSDoc boundary.** With `JSDocParsingMode.ParseNone` the scanner never reports a JSDoc comment, so `withJSDoc` never calls into `JSDocParser`; this module is checked with ParseNone. Provide `JSDocParser`'s entry points that the parser calls (e.g. `parseJSDocComment`) as stubs that throw `NotImplementedException("M5")`; M5 ports them. Everything else that concerns JSDoc in the main grammar (`parseJSDocAllType`, `parseJSDocUnknownOrNullableType`, `parseJSDocNonNullableType`, `parseJSDocFunctionType`, … outside `namespace JSDocParser`) belongs to this module.

The merged modules are the base: M1 (`src/NeverSharp.Faithful/Core/`) and M2 (`src/NeverSharp.Faithful/Scanner/`: `Scanner`, `CommentRange`, …). Use them; do not change them. Generated: enums and diagnostic messages (`src/Generated/`), the node classes, `NodeArray`, `NodeAllocator`, `NodeVisitor.ForEachChild` and `JSDocContainers.GetJsDoc`/`SetJsDoc` (TypeScript's `node.jsDoc` on any node) in `src/NeverSharp.Faithful/Generated/`.

## C# API (fixed; the dump tool and the benchmark call it)

- Namespace `NeverSharp.Faithful`, ported code `internal`; names and types as in [M1.md](M1.md)/[M2.md](M2.md).
- `parser.ts` → `internal sealed partial class Parser`. Its **instances** hold the state of `namespace Parser` (TypeScript keeps it in module variables; typescript-go in `type Parser struct`, `internal/parser/parser.go`). The file-level functions of `parser.ts` are **static** members of the same class.
- **Thread safety:** `Parser.CreateSourceFile` must be safe to call concurrently from many threads (the parse-only driver parses files in parallel, as typescript-go does). No mutable static state; a pool of parser instances is the permitted counterpart of typescript-go's `parserPool`/`getParser`/`putParser` (`internal/parser/parser.go`, `sync.Pool`).
- `nodeFactory.ts` → `internal sealed partial class NodeFactory`: instances are what `createNodeFactory` returns; file-level functions static.
- Called by the tools:
  - `static SourceFile CreateSourceFile(string fileName, string sourceText, CreateSourceFileOptions languageVersionOrOptions, bool setParentNodes = false, ScriptKind? scriptKind = null)` (and an overload with `ScriptTarget`).
  - `CreateSourceFileOptions` (parser.ts interface) with settable `LanguageVersion` (`ScriptTarget`) and `JsDocParsingMode` (`JSDocParsingMode?`), and its other members.
  - On `SourceFile` (a partial declaration in `Parser/`): the fields the generator leaves to the port (listed in a comment above `SourceFile` in `Nodes.g.cs`) with their ported types; in particular `List<DiagnosticWithLocation> ParseDiagnostics` and `List<DiagnosticWithLocation>? JsDocDiagnostics`. `DiagnosticWithLocation` (types.ts) exposes `int Code`, `int Start`, `int Length`.
  - `SourceFile.NodeCount` (generated field) set as TypeScript sets it.
- The tree the parser builds is TypeScript's: node kinds, `Pos`/`End`, `Flags`, children in the generated fields, `jsDoc` through `JSDocContainers`.

## Gate (run it, iterate until it passes)

```
<main>/.tools/node-24.21.0/node.exe harness/port/gate.mjs --module M34 --main D:/Private/Source/Andre/projects/NeverSharp
```

from the attempt's checkout. It runs:

1. Gate 2: Release build of `src/NeverSharp.Faithful` with the Track F analyzers (warnings are errors), header check.
2. Unit tests of M1 and M2 (regression).
3. G1a (regression): token-stream dump of all units, byte-identical to tsc 6.0.3.
4. **G1 with ParseNone**: `tools/NeverSharp.Dump ast --jsdoc-mode none` parses all 50,177 units of the equivalence corpus (each on its own thread with a 256 MB stack, 10 s timeout) and writes the canonical AST dump ([ast-dump-format.md](../ast-dump-format.md), format version 1: kind, pos, end, NodeFlags names per node in pre-order, then `!diag` parse diagnostics); `harness/astdump/compare-ast.mjs --jsdoc-mode none` compares each unit **byte for byte** with tsc 6.0.3's dump made with the same options (`dumps/ts-parsenone`). Outcomes (ok / timeout / error) must agree as well. It prints the first differing line of the first 15 differing units. The dump writer was checked by re-rendering tsc's own dumps (50,177 of 50,177 identical), so a difference is the parser's.

For iterating: the unit texts are in `<main>/artifacts/equivalence/units/<id>.txt` (file name and kind in `<main>/artifacts/equivalence/manifest.json`), tsc's dumps in `<main>/artifacts/equivalence/dumps/ts-parsenone/<id>.txt` (read-only). Probing single units or small sets with your own tools is free.

A **gate run** is one run of `gate.mjs`, or one run by hand of any of its parts over the whole test suite or corpus (build, unit tests, a full dump or comparison). An attempt ends when the gate passes or after **100** gate runs. Analyzer findings are fixed, never suppressed, except with a `#pragma warning disable` naming a reason tied to faithfulness; each is listed in the report.

## Working

- Helper files only in your own scratch folder `<session scratch>/M34-attempt-<n>/` (the session's scratch directory is shared; do not read other folders in it).
- Write C# files with the file-writing and editing tools, not with shell heredocs (they drop backslashes here).
- The module is large. You may delegate parts to sub-agents of your own model; they are part of your attempt, receive this brief, and follow the same rules (independence, scratch folder, no other attempts' work).

## Independence

Attempts do not see each other: do not read other worktrees, branches (including `attempts/*`) or attempt reports. Port from the inputs above.

## Report (the attempt's last message)

1. Model identifier (and sub-agents used, if any).
2. Gate result (the JSON summary line of the last gate run) and the number of gate runs.
3. Units not ported with reasons; `#pragma` suppressions with reasons.
4. Deviations from the TypeScript source that C# forced, each with file and line; every optimization with its typescript-go counterpart (file and function).
5. The commit hash of the attempt on its branch (`git commit -s`).

## Ranking (orchestrator, fixed before the attempts)

Survivors of the gate are ranked (pre-registration §5.2) by the median wall-clock of the M3+M4 workload, then by bytes allocated: `bench/NeverSharp.Benchmarks`, `M34.ParseTuningCorpus` — every file of the tuning corpus (24,511 files, read beforehand with sys.ts semantics) parsed with `Parser.CreateSourceFile(fileName, text, { LanguageVersion = Latest, JsDocParsingMode = ParseNone }, setParentNodes: false, scriptKind from the extension)`, single-threaded on one thread with a 256 MB stack, all `SourceFile`s kept alive until the end of the iteration. BenchmarkDotNet, NativeAOT, 3 warmup + 20 measured iterations, MemoryDiagnoser, attempts measured one after another on an otherwise idle machine. The winner is merged; all attempts, gate logs and numbers are recorded in [phase1-progress.md](../phase1-progress.md).
