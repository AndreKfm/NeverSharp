## Starting point

`main` after O11 (commit c756849), whose scanner is O23 variant B (ASCII lookup tables, keyword perfect hash) plus O11's `PeekPlainToken`. The scanner still takes about 26 % of the parse samples outside file reading (profile after O11, [track-o-profile.md](../track-o-profile.md)); `Scanner.Scan` 7.2 % and `ScanToken` 2.1 % attributed self time, `ScanString` 0.8 %. O23 variant C (SIMD, branch `attempts/O23/C`, commit 5fe8e5b; its report in [phase1-progress.md](../phase1-progress.md), O23) tied with B end to end, but its microbenchmark attributed large gains to SIMD identifier runs (44 ms of 122 ms scan-only) and string bodies.

## Goal

A faster scanner with a byte-identical token stream: ideas to evaluate, not prescribed — port the parts of O23 C that win on top of B (measure each: identifier runs, line-comment and block-comment bodies, string and template bodies), cheaper token-state bookkeeping in `Scan` (fewer field writes per token, `tokenValue` handling, flags), a tighter dispatch for the most frequent tokens, and `ScanToken`'s slow path order. Tokens, flags, positions, diagnostics and all scanner APIs (including `PeekPlainToken`) stay identical (G1a, Gate 1); thread safety and the NoAlloc contract as after O11.
