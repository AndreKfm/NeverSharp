## Goal

1. **Module interop of files (vscode, 2497).** The C# checker resolves default and namespace imports as for ambient modules only (`GetTargetOfModuleDefault` says so; `resolveESModuleSymbol` does not exist; namespace imports and exports call `ResolveExternalModuleSymbol` directly). Port from checker.ts (structure as in checker.go) what TypeScript 6.0.3 does with the Gate C options (module ES2022, moduleResolution Bundler, esModuleInterop and allowSyntheticDefaultImports on by default): `resolveESModuleSymbol` with its callers (`getTargetOfNamespaceImport`, `getTargetOfNamespaceExport`, `getExternalModuleMember`, `checkImportCallExpression`), `getTargetofModuleDefault` in full (`resolveExportByName`, `isOnlyImportableAsDefault`, `canHaveSyntheticDefault`, `reportNonDefaultExport`, the 1259 path), `cloneTypeAsModuleType` with the `target` and `originatingImport` links and their uses (`invocationErrorRecovery`, the related information in `checkTypeRelatedTo` and the other places that read `originatingImport`), `getTypeWithSyntheticDefaultOnly`, `getTypeWithSyntheticDefaultImportType`, `createDefaultPropertyWrapperForModule`. Branches that need Node16/NodeNext module kinds or project references are unreachable with these options: keep them out and say so in a comment. This changes types, not only diagnostics, and the equivalence check sees diagnostics only: port faithfully, and add a small repro per path to your scratch to compare with tsc (a few files as one program, both sides' diagnostics, plus a hover-free type check through a deliberate assignment error where a type matters).
2. **Union member order (tldraw, 2 messages).** `"auto" | "trackpad" | "mouse"` (tsc) against `"auto" | "mouse" | "trackpad"` (C#), likewise `"small" | "medium" | "wide" | "tiny"`: in C# a string literal type gets its id earlier than in tsc, somewhere earlier in the program. Find the first creation of the literal types concerned on both sides (instrument a copy of the oracle's typescript.js in scratch, as the orchestrator did for 001971; on the C# side a temporary probe that you remove before committing) and port the order of creation; do not sort to fake the order.
3. **2488 position (sentry, 1 message).** The same message at another position in `static/app/views/dashboards/widgetCard/visualizationWidget.tsx` (tsc 10045, C# 10726): find why the error node differs and port it.
