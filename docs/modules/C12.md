## Goal

1. **Equivalence on the tuning-check program.** `node harness/bench/check-equivalence.mjs --corpus tuning-check --skip-tsrs` (tsc 6.0.3 against `cs-o-aot-ws --check --single`; the C# driver is built at the start: `node harness/bench/build-cs.mjs --tracks optimized --runtimes aot-ws` after each change). The tsc side takes a while: cache its output in your scratch and rerun only the C# side while iterating. Target: identical. Each difference by cause; fix causes in the checker by porting what tsc does (do not sort or special-case to fake an order). A difference whose cause lies outside the checker (parser, binder, program layer) is reported, not fixed. If a cause turns out to be a tsc behaviour that cannot be reproduced without an unbounded effort, stop on it and report it with a repro.
2. **Parallel against single.** With 4 checkers C# reports 5,330 fewer diagnostics than with one. On the repository programs the difference is 0–18 (it comes from the order in which each checker creates types). Find what makes the difference here (per-file comparison of the two dumps: `--dump-diagnostics`), say whether typescript-go shows the same (`parse-go --check` against `--check --single` on the same list) and whether it is the same mechanism as on the repositories or a defect (state shared between checkers, a missing per-checker copy, a diagnostic lost). A defect is fixed; an inherent effect is explained with an example.
3. **Parallel stability.** At the end, `cs-o-aot-ws --check` on the tuning-check list 4 times: no crash, the same count each time. Remember b42ecc2: a checker never writes into a store shared with the other checkers (file stores, the program).

Target: the tuning-check program identical with tsc 6.0.3 single-threaded (or every remaining difference explained), the parallel difference explained or fixed, Gate C and the five repository programs unchanged.
