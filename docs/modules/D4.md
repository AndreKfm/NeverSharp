## Goal

Port, for the default options (target ES2025, `useDefineForClassFields` true, no `experimentalDecorators`):

**1. `transformers/esDecorators.ts`** (2,533 lines):
- class and member decorators in the standard form;
- `__esDecorate`, `__runInitializers`, `__setFunctionName`, `__propKey`;
- the class `static {}` blocks and `_classThis`;
- private names in decorated classes;
- auto-accessors;
- decorated class expressions.
- Also what tsc does with parameter decorators, which are not valid in this mode. Find out in tsc where they go away, whether in `ts.ts`, `esDecorators.ts` or the parenthesizer and modifier visitors, and port that.

**2. `transformers/classFields.ts`** (3,360 lines), as far as these options reach it:
- auto-accessors (`accessor x`);
- private names and `#x in obj` where the target needs a rewrite;
- the class-fields parts the decorator transformer depends on (`static` blocks with decorators, `this` and `super` in static initializers where tsc rewrites them).

**3. Shared parts these need:**
- `classThis.ts`;
- the rest of `namedEvaluation.ts` (D3 ported only what ESNext reaches);
- the parts of `destructuring.ts` they use, including the assignment-pattern node converter D1 left out;
- the `GeneratedNamePart` form of name prefixes (D1 left it out).

**Out of scope:** legacy decorators and decorator metadata (`experimentalDecorators`, `emitDecoratorMetadata`), and declaration emit (D5). Throw on paths the default options never reach, as D1–D3 did.

**Target:**
- All 3,363 of this module's units with an identical `.js` section, the one `.cts` unit (005669) included. Report the ones that are not, each with its cause.
- No regression in any section; the 46,820 identical `.js` sections stay identical.
- The printer gate stays identical in both modes after printer changes. Gate C stays identical after any checker change.
