# C0: checker oracle, program layer, checker skeleton — brief

Module C0 of Phase 3 ([phase3-plan.md](../phase3-plan.md); draft amendment [preregistration.md](../preregistration.md) §17). Track O only. Written by the orchestrator. Standing rules of [README.md](README.md); Phase 2+ rule: run only the tests and gates your change affects.

## Goal

The infrastructure every checker module is gated with, the program layer, and the data layout decision for the checker.

1. **TS oracle** `harness/astdump/dump-ts-checker.mjs` (same unit list, reading, script kinds and worker/timeout pattern as `dump-ts-binder.mjs`): per unit, a tsc 6.0.3 program of the unit's file plus the default library (`createProgram` with a custom `CompilerHost` that serves the unit from memory and the library files from typescript 6.0.3's `lib` folder; options `{}` plus `noResolve: true`; TypeScript 6.0.3's defaults otherwise — write the effective options into the dump header). Dump sections:
   - `diagnostics`: `getSemanticDiagnostics(unitFile)`, `getSuggestionDiagnostics(unitFile)` and `getGlobalDiagnostics()` in order: start, length, code, category, the message chain flattened (`flattenDiagnosticMessageText` with `\n`), related information;
   - `types`: TypeScript's own type baseline walker as reference (`src/harness/typeWriter.ts` in `external/typescript`: which nodes it visits, how it writes `typeToString` and symbol names) — reproduce its output for the unit file: per visited node in source order, the source text, `>` type line and symbol line as the baseline does;
   - library diagnostics are written once into a separate file (they are the same for every unit).
   CLI: `--jsdoc-mode` as the other oracles (measured mode first: `types` = ParseForTypeErrors; ParseAll optional), output under `artifacts/equivalence/dumps/ts-checker-<mode>/`, outcomes file, stamp. Determinism: two runs identical. Report the oracle's run time; if it is too slow for the gate (hours), propose a sampled gate (fixed, seeded subset for module iteration, full corpus for the final gate).
2. **Compare** `harness/astdump/compare-checker.mjs` with `--sections diagnostics,types`, summary counts (identical / differing / crashed).
3. **Track O program layer** (`src/NeverSharp.Optimized/Program/` or similar): `CompilerOptions` (the options Gate C uses, with TypeScript 6.0.3's defaults), a host abstraction, loading TypeScript 6.0.3's default library files (the same lib files the oracle uses; read from the pinned `harness/astdump/node_modules/typescript/lib` or a copy pinned in `artifacts/` — say which and why), parsing and binding them once per process and sharing them read-only between programs (thread safety), a `Program` holding its source files.
4. **Checker skeleton** (`src/NeverSharp.Optimized/Checker/`): types, signatures, symbol links and node links as handles in per-checker storage following Track O's style and typescript-go's checker structure (`internal/checker/types.go`); `Checker` with an empty `GetDiagnostics` / type walker surface the dump writer calls. Write the layout decision to `docs/phase3-checker-layout.md`.
5. **C# dump writer:** `tools/NeverSharp.Dump.Optimized --checker` writing the same format from Track O's program and checker (empty output for now).
6. **Gate:** `gate.mjs --track optimized --phase checker [--sections …] [--jsdoc-mode …] [--sample N]` runs Track O Gate 2 build + headers, the cached oracle, the C# checker dumps and the compare only.
