# O23: character classification and identifier/trivia scanning, up to 3 variants — brief

Steps O2 (character classification) and O3 (trivia and comment skipping) of Track O ([track-o-steps.md](../track-o-steps.md), [phase1-plan.md](../phase1-plan.md) §7) as one step, after the endpoint (later gains are reported next to G = 0.60, never instead of it). Pre-registration §5.4: at most 3 variants; variant A is `main` (no attempt). Written by the orchestrator before any attempt started. The standing rules of [README.md](README.md) apply. Runs in parallel with step O10 (side table), which changes `Arena/` and the emitter; touch only the scanner.

## Starting point

`main` after O9 (commit ca06679). Profile after O9 ([track-o-profile.md](../track-o-profile.md), last section): scanner self time about 12 % of all samples (`Scan` 5.9 %, `ScanIdentifier` 5.9 %), 14.5 % inclusive, about a quarter of the parse samples; tsrs needs 2.5–2.8× less user CPU for the whole parse (`results/track-o/probes/io/NOTE.md`). The scanner (`Scanner/Scanner*.cs`) reads the source through `SourceChars` (`char*` + length, step O1).

## The variants

| Variant | Approach | Ideas to evaluate (not prescribed) |
|---|---|---|
| **A: main** | the scanner as after O9 | — (measured as the reference) |
| **B: lookup tables, scalar** | a 128-entry (or 256) flag table for ASCII: identifier start/part, whitespace, line break, digit, punctuation class; `Scan`'s dispatch and the identifier, whitespace and comment loops on the table; non-ASCII through today's Unicode path | identifier runs as one tight loop over the table; first-character dispatch through a table of token kinds for single-character punctuators |
| **C: SIMD** | identifier runs, whitespace runs and comment bodies with `Vector128`/`Vector256` or `SearchValues<char>` + `IndexOfAnyExcept`/`IndexOfAny` (end of identifier, `*` or line break in block comments, line break in line comments) | short runs are the common case: measure the break-even, fall back to scalar below it; keep line-break and `hasPrecedingLineBreak` bookkeeping exact |

All variants keep: token stream, flags, positions, diagnostics and every scanner API byte-identical (G1a token dump and Gate 1), Unicode identifier semantics of the language version, JSDoc and template scanning behaviour, thread safety, and the NoAlloc contract (no allocation on the scan paths).
