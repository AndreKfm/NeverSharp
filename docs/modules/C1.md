## Goal

Port the checker's core from `external/typescript/src/compiler/checker.ts` (structure may follow typescript-go's `internal/checker`):

- `createTypeChecker` state and `initializeTypeChecker`: merging the global symbol tables of the library and the program files (`mergeSymbolTable`, `mergeSymbol`, global augmentations), the global types the checker looks up (`getGlobalType` …), intrinsic types (`any`, `unknown`, `string`, `number`, … `never`, error types), literal types and their freshness, `unionType` / `intersectionType` creation with tsc's member ordering (type ids in creation order) and reduction;
- symbol resolution: `resolveName` (all meanings, scopes, `globalThis`), `getSymbolOfNode`, `resolveEntityName`, `getMergedSymbol`, alias resolution (`resolveAlias`, `getTargetOfImport*`) as far as `noResolve` programs need, `getExportsOfSymbol` / `getMembersOfSymbol`;
- symbol and node links, `getTypeOfSymbol` for variables, parameters, properties and accessors from annotations (and the declared-type side of initializers as far as possible without C5), `getDeclaredTypeOfSymbol` for classes, interfaces, enums, type aliases and type parameters, `getTypeFromTypeNode` for the type node kinds that do not need instantiation (keywords, references to non-generic types, arrays/tuples of them, unions, intersections, literal types, type queries of resolved symbols, parenthesized types), resolved members of object types (`resolveStructuredTypeMembers` for non-generic classes/interfaces), signatures from declarations;
- the type walker surface the dump writer uses (types of expressions and declaration names for the `types` and `symbols` sections) wired to what C1 can compute, with `typeToString` delegated to a minimal path until C2 (keywords, literals, named types); `symbolToString` for symbol lines.

Leave stubs (clearly marked) for: instantiation and generics (C3), relations (C4), expression checking beyond identifiers/literals/property access of resolved members (C5), inference (C6), narrowing (C7), declaration checks (C8), JS/JSX (C9). Diagnostics from the core (duplicate identifiers across files, cannot-find-name, …) as `resolveName` produces them.
