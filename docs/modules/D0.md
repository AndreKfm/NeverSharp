# D0: emit oracle, Gate D harness, emit plumbing and comments — brief

Module D0 of Phase 4 ([phase4-plan.md](../phase4-plan.md); draft amendment [preregistration.md](../preregistration.md) §19). Track O only. Written by the orchestrator. The standing rules of [README.md](README.md) apply; run only the tests and gates your change affects.

## Goal

The infrastructure every emitter module is gated with, plus the parts of the emitter that do not need transformers.

**1. TS oracle `harness/astdump/dump-ts-emit.mjs`.** Use the same unit list, reading, script kinds and worker/timeout pattern as `dump-ts-checker.mjs`, with the same host.
- **Options per unit:** Gate C's options (`{}` with `noResolve: true`, plus `allowJs: true` for JavaScript and JSX units), plus `declaration: true` and `newLine: lf`.
- **Emit:** `program.emit()` with an in-memory `writeFile`, for the unit file only. The library files are never emitted.
- **Dump sections:**
  - `outputs`: each written file in write order, with its name relative to the unit's directory and its text;
  - `diagnostics`: the `diagnostics` of the emit result: start, length, code, category, message chain flattened with `\n`, related information, as the checker dump writes them;
  - `emitSkipped`.
- **Coverage report:** a separate file, not part of the gate. Per unit, which of the default-option transformers changed the tree: TypeScript, ESNext, ES decorators, class fields, ES module, declarations.
  - Find this out by running tsc's transformers with wrappers in the oracle process. Do not change TypeScript's sources.
  - Summarize per transformer how many units it touches, and how many units need none (emit of the parse tree, apart from type erasure).

**2. Compare and gate.**
- `harness/astdump/compare-emit.mjs` reports identical, differing and crashed units, per section (`js`, `dts`, `diagnostics`), with the first differing line of each differing unit.
- `harness/port/gate.mjs --phase emit --track optimized [--sample N]`: build, headers, cached oracle, C# dumps, compare, as `--phase checker` does.

**3. Track O emit plumbing** in `src/NeverSharp.Optimized/`:
- `Program.Emit(...)` with an emit host and in-memory write;
- output file names (`getOutputPathsFor`, the `.js`/`.jsx`/`.mjs`/`.cjs` and `.d.ts` extensions);
- `emitFiles` (`emitter.ts`) with an **empty transformer list for now**. Each later module adds its transformer.
- Until D2 lands, `.js` output differs wherever there are types. That is expected and shows as differing units.

**4. Comment emission in the printer** (`emitter.ts`):
- leading and trailing comments, detached comments, pinned comments (`/*!`), triple-slash and `@ts-` comments as tsc keeps them;
- `removeComments: false`, including `emitCommentsBeforeNode` / `emitCommentsAfterNode` and the comment ranges of synthesized nodes.

The printer gate ran with `removeComments: true`, so this is new across every `emit*` function. Extend the printer gate with a second mode, `removeComments: false`, in the oracle `dump-ts-printer.mjs` and in the C# dumper. Bring that mode to byte identity on all 50,177 units. Keep the existing mode identical.

**5. C# dump writer:** `tools/NeverSharp.Dump.Optimized --emit`, with the same format as the oracle.

**Target:**
- the printer gate in both comment modes identical on all units;
- Gate D's harness running end to end;
- every unit that needs no transformer (per the coverage report) identical in all three sections.

Report Gate D's counts per section at the end.
