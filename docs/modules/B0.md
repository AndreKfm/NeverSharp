# B0: binder oracle, dump, gate — brief

Module B0 of Phase 2 ([phase2-plan.md](../phase2-plan.md); draft amendment [preregistration.md](../preregistration.md) §15). Track O only; no Track F work. Written by the orchestrator. The standing rules of [README.md](README.md) apply, with the Phase 2 rule: run only the tests and gates your change affects.

## Goal

The infrastructure every binder module is gated with, plus the Track O data layout decision for binder output.

1. **TS oracle** `harness/astdump/dump-ts-binder.mjs`: for every equivalence unit (same unit list, file reading and script kinds as `dump-ts.mjs`; worker threads as there), `ts.createSourceFile(name, text, { languageVersion: Latest, jsDocParsingMode }, /*setParentNodes*/ true, scriptKind)`, then `ts.bindSourceFile(file, {})` (exposed by typescript 6.0.3), then a canonical text dump with three sections:
   - `symbols`: symbols numbered in first-reference order while walking the tree in `forEachChild` order (plus JSDoc where the parse dump includes it); per node that has one: `symbol`, `localSymbol`; per symbol: escaped name, `SymbolFlags` (numeric and names), declarations (node references: kind + pos + end), `valueDeclaration`, `members` and `exports` tables in insertion order (`Map` order), `parent` symbol, `constEnumOnlyModule`, `isReplaceableByMethod` if set; per container node: `locals` in insertion order; `nextContainer` chain from the source file.
   - `flow`: flow nodes numbered in first-visit order from the nodes that hold them (`flowNode`, `endFlowNode`, `returnFlowNode`, `fallthroughFlowNode`, and antecedents depth-first); per flow node: `FlowFlags` (numeric and names), the node it refers to (`node` reference, or for switch clauses the clause range), antecedent ids in order.
   - `diagnostics`: `bindDiagnostics` and `bindSuggestionDiagnostics` in order (start, length, code, category, message text), and node `flags` after binding for nodes whose flags the binder changed (compare against a parse-only copy, or record all node flags — choose what is simpler and deterministic).
   Same CLI shape as `dump-ts.mjs` (`--jsdoc-mode all|none|types` where `types` = `ParseForTypeErrors`), output under `artifacts/equivalence/dumps/ts-binder-<mode>/`. Determinism check: two runs byte-identical.
2. **Compare** `harness/astdump/compare-binder.mjs` (or an option of `compare-ast.mjs`): per unit byte compare, optional `--sections symbols,flow,diagnostics` filter, summary line and first differences as `compare-ast.mjs` prints them.
3. **C# dump writer skeleton** in `tools/NeverSharp.Dump.Optimized`: a `--binder` mode that parses with Track O, calls a (for now empty) Track O binder entry point `Binder.BindSourceFile(SourceFile, CompilerOptions)`, and writes the same dump format from Track O's binder data, so that B1–B3 only fill in the binder. With the empty binder the dumps differ — expected.
4. **Gate:** `harness/port/gate.mjs --track optimized --phase binder [--sections …] [--jsdoc-mode …]` runs Track O Gate 2 build + headers, the TS oracle dumps (cached when present and the oracle script unchanged), the C# binder dumps and the compare; nothing else (no parser gates).
5. **Data layout decision for Track O's binder output** (write it down in the module report and as a short design note `docs/phase2-binder-layout.md`): how symbols, symbol tables, flow nodes and the per-node binder fields (`symbol`, `localSymbol`, `locals`, `nextContainer`, `flowNode`, `endFlowNode`, `returnFlowNode`, `fallthroughFlowNode`) are stored in Track O (handles in per-thread slabs like `NodeStore`, side tables, or managed objects to start with), consistent with Track O's ownership rules (result owns its data; independent of later parses; thread safety; NoAlloc where the parser has it). Follow typescript-go's binder structure (`internal/binder/binder.go`) where it helps. Implement only the types and storage skeleton needed for the dump writer to compile.
