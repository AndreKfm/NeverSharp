# M1: Core (Track F) — brief for porting attempts

Module M1 of [phase1-plan.md](../phase1-plan.md) §4. Every attempt receives exactly this brief and the inputs it names (pre-registration §5.2). Written by the orchestrator before any attempt started.

## Scope

The 91 units listed in [M1-units.md](M1-units.md) (generated by `harness/port/modules.mjs --module M1` from the dependency slice): all of `core.ts` and `path.ts` that the parser reaches, the assertion part of `debug.ts`, and the text-range helpers of `utilities.ts`, `utilitiesPublic.ts` and `factory/utilitiesPublic.ts`. `CharacterCodes` and the other enums already exist (generated, `src/Generated/Enums.g.cs`).

A unit that has no meaning for C# values (a type test on JavaScript values such as `isArray` or `isString`, `hasProperty`, `emptyMap` as a JS `Map` constant) may be left out; each one left out is named with its reason in the attempt's report. Everything else is ported.

## Where the code goes

- New files only under `src/NeverSharp.Faithful/Core/`. One C# file per TypeScript file is the default.
- Do not change anything else: not `tests/`, `harness/`, `eng/`, `docs/`, `src/Generated/`, `src/NeverSharp.Faithful/Generated/`, project or props files. Extending a generated class through a `partial` declaration in `Core/` is allowed.
- Every file starts with the header of CONTRIBUTING.md (`Ported from src/compiler/<file>` with the TypeScript commit; `Port structure follows internal/<package>/<file>.go` with the typescript-go commit where a Go file was used).

## C# API (fixed; the gate calls it)

- Namespace `NeverSharp.Faithful`. Ported code is `internal` (`InternalsVisibleTo` the test project exists).
- One `internal static partial class` per TypeScript file, named: `core.ts` → `Core`, `path.ts` → `TsPath`, `debug.ts` → `Debug` (TypeScript's `namespace Debug`), `utilities.ts` → `Utilities`, `utilitiesPublic.ts` → `UtilitiesPublic`, `factory/utilitiesPublic.ts` → `FactoryUtilitiesPublic`. Later modules add to these partial classes.
- Method names: the TypeScript name in PascalCase. Overloads stay overloads.
- Types: positions, lengths and character codes `int`; numbers that can be fractional `double` (e.g. Levenshtein distances); `string`; `T | undefined` → nullable; readonly arrays `IReadOnlyList<T>`, mutable arrays `List<T>`, iterables `IEnumerable<T>`; callbacks `Func<…>`/`Action<…>`; TypeScript's `TextSpan` → a type with `Start` and `Length`.
- Errors: `throw new Error(m)` and `Debug.fail(m)` become exceptions whose `Message` is exactly TypeScript's message (`"Debug Failure. " + m`, `"start < 0"`, …).
- Signatures the gate calls (others are free within the rules above):
  - `TsPath`: `string NormalizePath(string)`, `string NormalizeSlashes(string)`, `int GetRootLength(string)`, `string GetBaseFileName(string)`, `string GetAnyExtensionFromPath(string)`, `string GetAnyExtensionFromPath(string path, IReadOnlyList<string> extensions, bool ignoreCase)`, `bool HasTrailingDirectorySeparator(string)`, `string RemoveTrailingDirectorySeparator(string)`, `string EnsureTrailingDirectorySeparator(string)`, `string? TryGetExtensionFromPath(string)`, `string GetNormalizedAbsolutePath(string fileName, string? currentDirectory)`, `string CombinePaths(string path, params string?[] paths)`, `bool FileExtensionIs(string path, string extension)`.
  - `Core`: `T? GetSpellingSuggestion<T>(string name, IEnumerable<T> candidates, Func<T, string?> getName)` (callable with `List<string>` and `c => c`).
  - `Debug`: `Assert(bool expression)`, `Assert(bool expression, string message)`, `Fail()`, `Fail(string message)` (optional parameters are fine).
  - `UtilitiesPublic`: `CreateTextSpan(int start, int length)`, `CreateTextSpanFromBounds(int start, int end)`.

## Gate (run it, iterate until it passes)

```
<main>/.tools/node-24.21.0/node.exe harness/port/gate.mjs --module M1 --main D:/Private/Source/Andre/projects/NeverSharp
```

run from the attempt's checkout. It runs Gate 2 (Release build of `src/NeverSharp.Faithful` with the Track F analyzers, warnings are errors; header check) and the M1 unit tests (`tests/NeverSharp.Faithful.Tests`), which compare about 600,000 calls with the results tsc 6.0.3 returned for the same arguments (`harness/port/vectors-m1.mjs`: every file name of the equivalence corpus, path edge cases, spelling suggestions). The gate prints the first differing calls.

Analyzer findings are fixed in the code, never suppressed, except with a `#pragma warning disable` that names a reason tied to faithfulness (e.g. a TypeScript name that a naming rule rejects); each suppression is listed in the report.

An attempt ends when the gate passes or after 30 gate runs.

## Independence

Attempts do not see each other: do not read other worktrees, branches or attempt reports. Do not look for a C# port of TypeScript elsewhere; port from the inputs above.

## Report (the attempt's last message)

1. Model identifier.
2. Gate result (the JSON summary line of the last gate run) and the number of gate runs.
3. Units not ported, each with its reason; `#pragma` suppressions with reasons.
4. Deviations from the TypeScript source that the C# type system forced, each with file and line.
5. The commit hash of the attempt on its branch (commit with `git commit -s`).

## Ranking (orchestrator, fixed before the attempts)

Survivors of the gate are ranked (pre-registration §5.2) by the median wall-clock of the M1 workload on the tuning corpus, then by bytes allocated: for every unit file name of the tuning corpus, the path work of `parseSourceFile` (`parser.ts:1742`, `:1804`): `NormalizePath(name)`, then `isDeclarationFileName` on the result, i.e. `GetAnyExtensionFromPath(name, [".d.ts", ".d.cts", ".d.mts"], false)`, `FileExtensionIs(name, ".ts")` and `GetBaseFileName(name)`; 20 measured runs after 3 warmup runs in one process (BenchmarkDotNet, MemoryDiagnoser), NativeAOT. The winner is merged; all attempts, their gate logs and the numbers are recorded in [phase1-progress.md](../phase1-progress.md).
