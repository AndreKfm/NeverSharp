## Goal

1. **C# Track O:** a parse+bind mode in the parse driver, e.g. `--bind` (or a separate executable name, whatever fits the driver contract and `build-cs.mjs` best): every file parsed exactly as now and then bound with Track O's `Binder.BindSourceFile(sourceFile, new CompilerOptions())` inside the same work item; every result kept alive until the end; the JSON line additionally reports something that proves binding happened (e.g. the total number of symbols created). Track F gets no bind mode.
2. **typescript-go 7.0.2:** the same in `harness/bench/go/parse.go` (a `--bind` flag): after `parser.ParseSourceFile`, call typescript-go's binder for the file (`internal/binder`, `binder.BindSourceFile(file, options)` or what 7.0.2 offers) in the same work-group item, with default compiler options; report a comparable count. Keep the build reproducible as `build-go.mjs` does (pinned commit, overlay, flags); typescript-go's own default build settings (`GOAMD64=v1`) stay.
3. **tsrs:** check whether tsrs 0.18.0 exposes a binder that can be called per file; if yes, add the same `--bind` to `parse-rs`; if not, document why not (it is then not reported, as §15 says).
4. **Configurations** in `bench.mjs`: `cs-o-<runtime>-bind` and `-single` variants for the four runtimes, `tsgo7-bind`, `tsgo7-bind-single` (and `tsrs-bind*` if 3. works), with the same validation (file counts, priority, driver name; the bind count > 0).
5. **Functional check (not a measurement):** every new configuration runs once on the five benchmark repositories and the tuning corpus and reports the expected file counts and a non-zero bind count; no timing.
