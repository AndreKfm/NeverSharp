## Goal

**1. Symbol ids in generated names (author's decision, 2026-11-03).**
- **Why:** the number tsc prints is its process-wide `getSymbolId`. It depends on how many symbols the oracle's shared worker had numbered before the unit, so even tsc prints another number for the same file alone. It is not part of the unit's output semantics.
- **Fix:** `harness/astdump/compare-emit.mjs` replaces that number with a placeholder, on both sides, before comparing. This applies only to the names tsc builds from a symbol id:
  - the late-bound member name `__@<name>@<id>`;
  - the local names derived from it (`_____sym_<id>` and the like).
- Make the pattern as narrow as tsc's name construction allows. Report how many units and lines of the corpus it changes on the tsc side; it must not touch any other text.
- The oracle and its dumps stay unchanged.
- The orchestrator writes the rule into §19; do not edit `docs/preregistration.md`.

**2. 008381.** Find the assertion in tsc 6.0.3 that fails (`visitEachChildOfIndexSignatureDeclaration`, through `Debug.assertNode`), and port it faithfully, so that Track O fails on this unit the way tsc does. 000863, 000913 and 002379 were handled the same way. If the cause turns out to be something other than a ported assertion, report it before you change anything else for this unit.
