# Phase 4: Track O emitter layout (modules D0–D5)

Decided in module D0 ([modules/D0.md](modules/D0.md), [phase4-plan.md](phase4-plan.md)) and extended in module D1 ([modules/D1.md](modules/D1.md): transformation context, emit helpers, emit resolver, synthesized nodes) and module D2 ([modules/D2.md](modules/D2.md): the TypeScript transformer, the printer's parenthesizer rules for substitutes, names of namespaces and enums), module D3 ([modules/D3.md](modules/D3.md): the ESNext, ES module and CommonJS module transformers) and module D4 ([modules/D4.md](modules/D4.md): the ES decorators and class fields transformers, the rest of named evaluation, `classThis.ts`, the assignment-pattern converters, `GeneratedNamePart` prefixes). Module D5 ([modules/D5.md](modules/D5.md)) added the declaration transformer, the resolver's declaration-emit entries, the node builder's declaration mode and the symbol tracker (section "Declaration emit (module D5)"); module D6 may refine the details below.

## Transformed trees and synthesized nodes (module D1)

**Decision: the transformers write into an emit copy of the file's store.** Track O's nodes are handles of one store, so a transformed tree, which mixes parse tree nodes and new nodes, must live in one store. Writing into the file's own store would break the rule that nothing writes into a file's store (other checkers read it concurrently at the endpoint), and TypeScript also annotates parse tree nodes with emit nodes. So `NodeStore.CreateEmitCopy()` copies a committed store (records, object slots, side table, dense parents, list headers and elements, arena characters and interned texts) into memory of the copy's own, sharing the source text, and every handle of the file is the same handle in the copy. The checker and the resolver keep reading the file's own store; a parse tree node the transformers pass to the resolver is mapped to the file with its handle. The copy is released after the file's emit. Cost: one copy of the file's arenas per emitted file (to be profiled after Gate D, D6).

- **Synthesized nodes:** a copy's new nodes start with pos and end -1 and `NodeFlags.Synthesized` (TypeScript's `syntheticFactory`): the store writes its `newNodeFlags` and `newNodePos` into every new record (`CreateNode` and the generated `New{Class}`; 0 in the parser's stores, so parsing is unchanged; generator `tools/NeverSharp.Generate/emit-optimized.mjs` changed accordingly).
- **cloneNode:** `NodeStore.CloneRecord` copies a node's record, object slots and side fields except those TypeScript's node constructor sets (parent, original, modifier flags cache, emit node). The binder's data (flow nodes, symbols) is not in the store and is not copied; nothing reads it from clones.
- **Original nodes, text ranges:** the side field `Original` (`setOriginalNode`, with the emit node merge), `SetTextRange` on the record's pos and end, as before.
- **Emit nodes** (`Factory/EmitNode.cs`): the rest of `emitNode.ts` the transformers use: emit flags and internal flags, comment range (a node as the range is snapshotted to its pos and end), source map range (stored, never read: no source maps), synthetic leading and trailing comments, constant values, emit helpers (`AddEmitHelper(s)`, `MoveEmitHelpers`, `GetEmitHelpers`), type node, auto-generate info (`AutoGenerateInfo`: flags, id, prefix, suffix; since D4 the `GeneratedNamePart` form of a prefix as `PrefixPart`, formatted by the printer with the generated or plain text of its node as `formatGeneratedNamePart(part, generateName)` does), generated import reference, `DisposeEmitNodes`.
- **Generated identifiers:** `nextAutoGenerateId` is process-wide (`Interlocked`): ids only need to differ.

## Not yet supported (and how it fails)

- TypeScript transformer (`Emitter/Transformers/TypeScript.cs`, D2): complete for the default options. Not ported (outside them): legacy decorators and decorator metadata, the class IIFE of targets below ES2015, bundles.
- Destructuring (`Emitter/Destructuring.cs`, D2): only `flattenDestructuringAssignment` for a variable declaration with a binding pattern at `FlattenLevel.All` (exported destructured variables of a namespace). An object rest element there throws `NotSupportedException` (`__rest` helper); destructuring assignments, `flattenDestructuringBinding` and `FlattenLevel.ObjectRest` are not reached by the transformers of the default options (the ES decorators and class fields transformers use no destructuring flattening; D4 ported the assignment-pattern node converters).
- ESNext transformer (`Emitter/Transformers/ESNext.cs`, D3): complete (the assignment-pattern converter it needs for a destructured top-level variable after a top-level `using` since D4). Named evaluation (`Emitter/NamedEvaluation.cs`): complete since D4.
- ES decorators transformer (`Emitter/Transformers/ESDecorators.cs`, D4): complete for standard decorators below ESNext. Legacy decorators and decorator metadata are other options (`TypeScript.cs` and `Transformer.cs` throw).
- Class fields transformer (`Emitter/Transformers/ClassFields.cs`, D4): target ES2022 and later with `useDefineForClassFields` true (auto-accessors, private static elements of class-decorated classes, class aliases); other targets and `useDefineForClassFields: false` throw `NotSupportedException` when the transformer is created, `WillHoistInitializersToConstructor` (never set under these options) throws in `transformConstructor`.
- ES module transformer (D3): complete for module kinds ES2015..ESNext without `rewriteRelativeImportExtensions`; `--module preserve`, node16+ (`createRequire` shim) and rewritten specifiers throw.
- CommonJS transformer (`Emitter/Transformers/CommonJSModule.cs`, D3): the CommonJS path of `module.ts` for files whose emit module format is CommonJS (`.cts`; `.cjs` files are JavaScript, whose `.js` output is blocked). AMD, UMD, `rewriteRelativeImportExtensions`, external helpers (`importHelpers`) and JSON modules with `outFile` are not ported; a destructuring assignment to exported names (`flattenDestructuringAssignment` of an assignment) throws.
- Custom transformers, `emitOnly`, `forceDtsEmit`, build info, source maps, `outFile`, `outDir`, `noEmit`, `noEmitOnError`, `emitBOM`, `importHelpers`, `noEmitHelpers`: outside Gate D's options.
